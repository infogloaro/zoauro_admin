System flow

The three apps only write through the signed intake API. The admin panel acts on the Core, and every decision goes back to the apps as a signed webhook. One writer per field: apps never write status, verification, commission, zone or admin-disabled.

Built today: the Core, the admin panel and the outbox table. Not yet: the intake API (folder is empty) and the outbox publisher, so apps cannot send onboarding requests or receive decisions yet.

Rules on every page

Every list

  • Search, filters, sort, server pagination (25 per page).
  • Sticky header and pagination footer. Row action menu; row checkboxes only when bulk actions exist.
  • All of it lives in the URL: ?page&pageSize&sort&q&filters&zone.
  • Zone column and Zone chip when the scope covers more than one zone.
  • Phones and emails masked; Reveal is an audited action.
  • CSV export only with the export permission; large exports run in the background.

Every state

  • Loading: skeleton shaped like the page.
  • Empty: one line and the primary action, if allowed.
  • No results: "No matches" and Clear filters.
  • Error: message, request id, Retry.
  • Forbidden: "You don't have access" and a link home.
  • Stale: "This record changed. Reload."
  • Zone removed mid-session: "No longer available".

Forms and actions

  • Add and edit open in a side sheet or dialog. Labels above fields, * for required.
  • Validate on blur and on submit; focus the first invalid field; submit disabled while saving.
  • Leaving with unsaved changes asks first.
  • Destructive actions confirm and name the target. Risky ones (access, zones, vendor decisions, security, payouts) ask for the password, or password + code.
  • Toasts: success clears after 4 s, errors stay until dismissed.

Formats

  • Money in Indian grouping: ₹12,48,320. Stored as paise.
  • Dates: 09 Oct 2026, 14:30 in India time.
  • Status chips always carry text. Green: active, delivered, paid, verified. Orange: pending, preparing. Blue: assigned, out for delivery. Red: cancelled, failed, suspended, rejected. Grey: inactive, draft.
  • Sentence-case labels; buttons are verbs: "Approve vendor", "Save changes".

Competitor patterns

What Zomato, Swiggy, Uber Eats Manager, DoorDash, Deliveroo, Foodpanda, StackFood/6amMart and Shef do on the same jobs, and how ZOAURO compares. Items marked "Proposal" are not in the spec; each needs an owner decision in doc 03 before anyone builds it.

PatternSeen atZOAURO todayWhere it would live

How others run vendor onboarding

  • Zomato: FSSAI licence per outlet is mandatory; verification takes about 3–7 days, sometimes with a visit.
  • StackFood / 6amMart: separate "new joining requests" lists for restaurants and riders, with custom required fields per platform.
  • Shef: long home-cook onboarding with a food-safety test, then random audits and a rating floor.
  • Swiggy: partner onboarding centres for riders, shift blocks after approval.

Where ZOAURO is already ahead

  • Per-zone access with deny-wins overrides and per-zone refund limits. StackFood and Enatega have flat roles.
  • Separate verification and status, password check on every vendor decision, audited reveal of contact details.
  • Menu edits gated by approval while the live value stays on sale.
  • Every admin decision reaches the apps through a signed, retried event with replay.

Sources: Uber Eats Manager learning centre, DoorDash merchant help, Deliveroo help centre, 6amTech docs and blog, Inc42 (Zomato, Swiggy), TechCrunch (Shef). Zomato and Swiggy internal ops tools are not public, so those rows are partly inferred.

The owner answered the open list on 18 Oct; the decisions are D143–D166 in doc 03. Almost every business value becomes a dynamic Super Admin setting in the Control Panel, with a default until the Super Admin changes it. Flow steps beyond the decision text are marked as proposals.

Hotels: rooms, tables, pre-ordersD150, D144Room booking, table booking and pre-orders (a traveller orders for a chosen time and place; the partner delivers at that time). Access, rules and monitoring in the admin panel; existing admin roles only in phase 1
Auto-assign partnersD154Per-zone setting, off by default: nearest available partner within 5 km, 60 s offer, then the next; manual fallback with an alert. Vendor side can also pick a nearby partner
