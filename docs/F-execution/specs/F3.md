## Summary
Hotels get the same document step as restaurants, homemakers and partners. Documents are stored in vendor_documents with vendor_type 'HOTEL' (no migration), uploaded through the existing presign, PUT and confirm chain (purpose VENDOR_DOC), and checked against the HOTEL party of the Control Panel setting onboarding.documents. That party's default becomes the D182/H2 list: GST, PAN, Trade licence and Bank details mandatory, FSSAI optional.

New routes, copied from vendors (D120/D131):
- POST /hotels/{id}/documents (hotels:edit)
- GET /hotels/{id}/documents/{docId}/url (hotels:view; 300 s signed link, audited)
- POST /hotels/{id}/documents/{docId}/verify (hotels:status; reject needs a note, PENDING only)

GET /hotels/{id} and every hotel write now return documents[] and checklist (null when the party is not configured).

New rule: POST /hotels/{id}/verification with decision VERIFIED returns 409 INVALID_STATE_TRANSITION, with meta.missing, until the newest document of every mandatory catalogue type is accepted. Rejecting a hotel stays possible without documents.

Web: HotelDetailPage gets a Documents card. Its type picker comes from the hotel checklist plus "Other", and it has View, Accept, Reject and upload. Verify in the Decisions card is disabled until the mandatory documents are accepted, with a tooltip naming what is missing.

The demo seed uploads and accepts documents so that the LIVE hotels verify, leaves one mandatory document missing on Kovai Grand Inn (REVIEW), and rejects the trade licence on Lotus Comforts.

## Performance
- Detail read: GET /hotels/{id} adds one indexed query, vendor_documents WHERE vendor_type='HOTEL' AND vendor_id=$1 AND deleted_at IS NULL, using the existing index (vendor_type, vendor_id). It runs in Promise.all with occupiedRooms and the catalogue read. The catalogue comes from the settings reader's cache (`effective` is cached and invalidated on save), so no extra DB hit when the cache is warm.
- Payload: documents are a handful per hotel (catalogue max 30 types), so no pagination; the same as vendors and partners.
- Uploads: file bytes go browser → MinIO/S3 directly via the 300 s presigned PUT. The API only does presign, HEAD and a 16-byte read on confirm and attach. The signed GET link is generated locally (no S3 round trip).
- Uploads ownerOf: hotels are asked last, after up to 3 primary-key lookups (restaurant, homemaker, partner). That costs well under a millisecond each; no change needed.
- Verify gate: runs inside the existing transaction after SELECT … FOR UPDATE on the hotel; one extra indexed read.
- Lists: GET /hotels list and exports are unchanged (no document join), so the list stays fast. Web: the hotel detail already uses staleTime 15 s; after a write, useInvalidateHotels refreshes only the hotels keys.
